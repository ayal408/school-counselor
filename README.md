# מרחב — מערכת ליועצת בית הספר

גרסת פיתוח 0.1.0. לקוח React + TypeScript בעברית וצד שרת Python.

## ארכיטקטורה

בהתאם להפרדת השירותים ב־DOMix, בבראנץ `dev`:

| רכיב | טכנולוגיה | אחריות |
| --- | --- | --- |
| counselor-client | React 19, TypeScript, Vite, TanStack Query, Zustand, Axios | ממשק RTL; access token בזיכרון בלבד |
| auth-server | Python / FastAPI | התחברות, הנפקת JWT, refresh cookie ויציאה; ללא גישה ישירה ל־DB |
| counselor-server | Python / FastAPI, SQLAlchemy, Alembic | נתונים, הרשאות, סיסמאות Argon2, הצפנה ומיגרציות |
| postgres | PostgreSQL 16 | אחסון נתונים, refresh hashes ויומן פעולות |
| nginx | Nginx | לקוח וניתוב `/api/auth/*` לשירות האימות ו־`/api/*` לשרת הנתונים |

שרת הנתונים בלבד מחזיק חיבור למסד. שירות האימות מתקשר איתו ב־API פנימי עם מפתח שירות. נתיבי `/internal` אינם נחשפים דרך ה־gateway. אין הרשמה ציבורית.

## מה עובד

- התחברות, חידוש token חד־פעמי ויציאה עם ביטול refresh בשרת.
- רשימת תלמידות, חיפוש, הוספה, API לעריכה והעברה לארכיון.
- כרטיס תלמידה ותיעוד פגישות ידני בציר זמן.
- הקלטה בהסכמה, תמלול עברי וטיוטת סיכום דרך OpenAI, Google Gemini או Groq, בכפוף להפעלה וחיבור API.
- אישור מקצועי נדרש לשמירת תיעוד בסיוע AI; השמע אינו נשמר באתר.
- יומן פגישות לפי יום או שבעה ימים, קביעת פגישה, בדיקת חפיפות ושינוי מצב.
- משימות מוצפנות עם מועד יעד, סימון השלמה, סינון מצב והצגה בכרטיס תלמידה.
- הרשאות לפי בעלות ושיתוף מפורש לצפייה; בדיקת משתמשת פעילה וגרסת התחברות בכל בקשה.
- הצפנת שם, כיתה, סיבת הפניה, הערות וסיכומים באמצעות Fernet לפני שמירה.
- יומן פעולות ללא תוכן מקצועי; כותרות no-store; הגנת Origin ו־XHR לפעולות cookie; הגבלת קצב ב־gateway.
- נעילת ממשק לאחר 15 דקות ללא פעילות; token גישה תקף עד 10 דקות.

## הרצה עם Docker

1. העתיקי `.env.example` ל־`.env`.
2. החליפי את סיסמת PostgreSQL ושני הסודות בערכים אקראיים נפרדים. השתמשי בסיסמת DB אלפאנומרית כדי שתהיה תקינה בתוך URL.
3. צרי מפתח Fernet (אחרי התקנת cryptography):

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

שימי את הערך ב־`DATA_ENCRYPTION_KEY`. אין לשמור מפתחות בגיט. איבוד המפתח מונע קריאת המידע, ולכן יש לגבות אותו בנפרד ובאופן מוגן.

```bash
docker compose up --build -d
docker compose exec counselor-server python -m app.create_user
```

הפקודה האחרונה יוצרת יועצת מורשית עם סיסמה אינטראקטיבית שאינה נשמרת בהיסטוריית הפקודות. פתחי http://localhost:8088.
המיגרציות מיושמות לפני עליית השרת. אין נתוני דוגמה או סיסמת מנהל בקוד.

`COOKIE_SECURE=false` מיועד ל־HTTP מקומי בלבד. בהפעלה אמיתית נדרשים HTTPS, `COOKIE_SECURE=true` ו־`CLIENT_ORIGIN` שתואם בדיוק לכתובת האתר. השירותים ו־PostgreSQL אינם חושפים פורטים למחשב המארח.

## בדיקות

```bash
pip install -r counselor-server/requirements.txt
python -m pytest counselor-server/tests auth-server/tests -q
cd counselor-client
npm ci
npm run build
```

בדיקות Python יוצרות נתונים פיקטיביים ב־SQLite בזיכרון בלבד ולא מתחברות ל־DB של הפיתוח או הייצור. הן בודקות בידוד משתמשות, הצפנה, אימות, חסימת נתיב פנימי, refresh חד־פעמי וארכוב. CI מפעיל את הבדיקות ואת בניית React.

## שגיאת SSL בעת בנייה ברשת מסוננת

`CERTIFICATE_VERIFY_FAILED` בזמן pip או npm עשוי להצביע על תעודת CA של סינון רשת או proxy שהמחשב מכיר אך Docker אינו מכיר. השגיאה "No matching distribution" במצב זה אינה ראיה שחסרה גרסת החבילה.

ב־Windows, ברשת NetFree שכבר מותקנת בה תעודת שורש מהימנה, הריצי מתוך תיקיית הפרויקט:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

הסקריפט מאגד את כל תעודות השורש של NetFree שכבר מהימנות במחשב, ומפסיק אם לא נמצאה אף תעודה. ברשת אחרת, או אם לא נמצאה תעודה, קבלי ממנהל הרשת תעודת CA ציבורית והעבירי נתיב:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -CertificatePath "C:\certs\network-ca.crt"
```

אין ביטול של אימות SSL. התעודה מועברת בתור BuildKit secret, משמשת רק בהתקנת התלויות, אינה נשמרת בתמונה ואינה עולה לגיט. קובץ compose.local-ca.yml הוא אפשרות לפיתוח מקומי בלבד; בנייה רגילה אינה משתמשת בתעודה. תעודה לא תקינה או חסרה אינה נעקפת.

לאחר עליית השירותים אפשר ליצור משתמשת:

```powershell
docker compose exec counselor-server python -m app.create_user
```

## הפעלת הקלטה ותמלול

בכרטיס תלמידה פתחי תיעוד פגישה. ניתן להקליט עד 10 דקות ו־20MB, להשהות, להמשיך ולעצור, לתמלל לעברית, לתקן את התמלול וליצור טיוטת סיכום. התמלול מועתק להערות הפגישה. שינוי תמלול דרך מסך ההקלטה מנקה את הסיכום הקודם. כל שינוי בהערות או בסיכום מבטל את אישור הבדיקה, ונדרש אישור מחדש לפני שמירה.

הקלטה דורשת הרשאת מיקרופון ודפדפן תומך. localhost מתאים לפיתוח; בהפעלה מרחוק נדרש HTTPS. השמע מוחזק זמנית בזיכרון הדפדפן והשרת ואינו נשמר במסד או בקובץ מקומי. מעבר מסך מאבד את השמע שטרם תומלל. תמלול וסיכום נשמרים מוצפנים רק לאחר פעולת שמירת הפגישה. אישור הסכמה לעיבוד נרשם ביומן פעולות עם מזהה היועצת, התלמידה ומועד הבקשה, ללא תוכן מקצועי.

להפעלה, עדכני בקובץ .env המקומי בלבד:

```dotenv
AI_ENABLED=true
OPENAI_API_KEY=your-private-api-key
OPENAI_TRANSCRIPTION_MODEL=whisper-1
OPENAI_SUMMARY_MODEL=gpt-4.1-mini
```

המפתח חייב להיות בעל גישה למודלים ולהפעלת API בחשבון הספק. אין להזין אותו בלקוח, ב־GitHub או בהודעות. הקריאות עשויות להיות בתשלום לפי תנאי הספק. המודלים ניתנים להגדרה; לתמלול נדרש מודל התומך בשדות language=he ו־response_format=json.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

השירות כבוי כברירת מחדל. לפני הפעלה עם מידע אמיתי יש להסדיר הסכמה, הרשאה להעברת מידע לספק שנבחר ומדיניות שמירה אצל הספק. store=false בסיכום אינו הבטחה לאפס שמירה של הספק. אין לשלוח שמות ופרטי תלמידות מיותרים; הבקשות אינן מצרפות אוטומטית את פרטי כרטיס התלמידה.

לרשת NetFree, compose.local-ca.yml מעביר את תעודת הרשת לשרת הנתונים גם בזמן ריצה, כדי לאמת את חיבור ה־AI. האימות נשאר פעיל; בנייה רגילה אינה כוללת את התעודה. מגבלת קצב AI נאכפת ב־Nginx, ושתי בקשות עיבוד לכל היותר מטופלות בו־זמנית בכל תהליך שרת.

בדיקות AI משתמשות בספק מדומה ולא מבצעות קריאות בתשלום. הקלטה בדפדפן וקריאה אמיתית לספק דורשות בדיקה מקומית עם מפתח והסכמה.

## בחירה בין ספקי AI

במסך ההקלטה יש בחירה בין OpenAI, Google Gemini ו־Groq. ספק זמין רק כאשר AI_ENABLED=true וקיים עבורו מפתח בשרת. ברירת המחדל נקבעת לפי AI_PROVIDER; אם הספק המועדף אינו מוגדר, נבחר ראשון מבין הספקים המוגדרים לפני שהמשתמשת מאשרת הסכמה. אין החלפה אוטומטית לאחר כשל, ומעבר ידני לספק אחר מבטל את אישור ההסכמה המקומי עד לאישור מחדש.

| ספק | מפתח בשרת | מודלים בהגדרות |
| --- | --- | --- |
| OpenAI | OPENAI_API_KEY | OPENAI_TRANSCRIPTION_MODEL, OPENAI_SUMMARY_MODEL |
| Google Gemini | GEMINI_API_KEY | GEMINI_MODEL לתמלול ולסיכום |
| Groq | GROQ_API_KEY | GROQ_TRANSCRIPTION_MODEL, GROQ_SUMMARY_MODEL |

ניתן להגדיר מפתח אחד או כמה. מפתחות אינם מופיעים במסך ההגדרות או בתשובות API. סטטוס ״מוגדר ומופעל״ מציין הגדרה בלבד, ואינו מוכיח שהמפתח, המכסה או המודל תקינים. מודלי ברירת המחדל נמצאים ב־.env.example וניתנים להחלפה בהתאם לזמינות ולהרשאות בחשבון הספק.

דוגמה להפעלת Gemini בקובץ .env המקומי:

```dotenv
AI_ENABLED=true
AI_PROVIDER=gemini
GEMINI_API_KEY=your-private-key
GEMINI_MODEL=gemini-3.8-flash
```

מגבלת השמע היא 20MB ב־OpenAI וב־Groq, ו־8MB ב־Gemini בשל העברת השמע בתוך בקשת JSON. זמן ההקלטה המרבי בממשק נשאר 10 דקות. הספקים מקבלים את ההקלטה או התמלול רק לאחר אישור, וכל תוצר עדיין דורש בדיקה מקצועית. מדיניות השמירה והתשלום שונה בין הספקים ונדרש לבדוק אותה לפני שימוש במידע אמיתי.

[תיעוד OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text) · [תיעוד Gemini](https://ai.google.dev/gemini-api/docs/audio) · [תיעוד Groq](https://console.groq.com/docs/speech-to-text)

## עיצוב הממשק

לוח הבקרה כולל ברכה אישית, נתוני תלמידות ופגישות, הפגישות הקרובות והמשימות הפתוחות מתוך השרת. שודרגו כרטיסי תלמידות, התפריט, מסך הכניסה, הטפסים, סטטוסים ומסך ספקי AI. העיצוב מותאם ל־RTL, למסכים קטנים, למיקוד מקלדת ולהעדפת תנועה מופחתת. אין פונטים או תמונות חיצוניים.

## בוחר תאריכים עברי

שדות התאריך ביומן, בתכנון פגישות, במשימות ובתיעוד פגישה משתמשים ב־[react-hebrew-datepicker](https://github.com/Es-Mes/react-hebrew-datepicker), גרסה 1.1.3. מוצגים לוח עברי ולועזי יחד, עם כיווניות RTL וצבעי המערכת. השעה נבחרת בנפרד; השמירה נשארת במועד UTC תקני לאחר המרת הזמן המקומי.

התלות מותקנת מ־npm עם גרסה נעולה. postinstall מפעיל תיקון מקומי ממוקד לפונקציית ההמרה של 1.1.3, שמוסיפה יום וממירה חצות מקומית ל־UTC. התיקון משתמש בתאריך האזרחי של היום שנבחר ללא הסטה, ונעצר אם גרסת הספרייה או מבנה הקוד משתנים. בדיקת ההמרה רצה כחלק מהבנייה באזורי הזמן ירושלים, UTC וניו יורק. אין שינוי במסד הנתונים.



## הגדרות וניהול

מסך ההגדרות כולל אבטחה, ספקי AI, גיבוי ושחזור, ולמנהלת גם ניהול משתמשות. פעולה רגישה מחייבת הזנת סיסמה מחדש, ואם הופעל MFA גם קוד חדש מהאפליקציה או קוד שחזור. אין להשתמש שוב באותו קוד אימות לפעולה נוספת.

### מנהלת ומשתמשות

מיגרציה 0004 מוסיפה את הרשאות הניהול: בהתקנה קיימת היא ממנה למנהלת את המשתמשת הפעילה הראשונה לפי סדר כתובת המייל. בהתקנה חדשה המשתמשת הראשונה שנוצרת בפקודת create_user מקבלת תפקיד מנהלת, והשאר יועצות. מנהלת יכולה להוסיף חשבונות, להקצות תפקיד מנהלת או יועצת, להשבית חשבונות ולאפס סיסמה. היא אינה מקבלת גישה אוטומטית לכרטיסים של אחרות, ואינה יכולה להשבית את עצמה או להסיר את תפקיד המנהלת שלה דרך הממשק. שינוי משתמשת מבטל את כל ההתחברויות הקודמות שלה, כולל JWT שכבר הונפקו.

בכרטיס תלמידה בבעלותך ניתן לשתף לצפייה עם חשבון פעיל אחר. השיתוף כולל פרטי תלמידה, פגישות, משימות ויומן; אינו כולל עריכה, AI או שיתוף נוסף. ביטול שיתוף נאכף בבקשות הבאות לשרת. תוכן שכבר נצפה אינו ניתן למחיקה מזיכרונה של המקבלת.

### ספקי AI אישיים

ניתן להזין מפתחות אישיים, לבחור מודלים ולהפעיל או לכבות כל ספק עבור החשבון. המפתחות מוצפנים באמצעות DATA_ENCRYPTION_KEY; הממשק מקבל רק מצב הגדרה, ללא המפתחות. שדה מפתח ריק שומר את המפתח הקיים; יש אפשרות מחיקה מפורשת. הגדרה אישית גוברת על סביבת השרת עבור אותו ספק, כולל האפשרות להשאירו כבוי. הפעלה אישית אינה דורשת AI_ENABLED=true, המשמש רק את הגדרות הסביבה. רק ספקים עם מפתח שמור ופעיל זמינים. ב־Gemini אותו מודל משמש לתמלול ולסיכום.

בדיקת חיבור קוראת לרשימת המודלים בכתובת קבועה של הספק; היא אינה שולחת מידע מקצועי ואינה בודקת שהמודלים שנבחרו רשאים לעבד שמע או סיכומים. הסכמה לעיבוד ואישור מקצועי של התוצרים נשארים נדרשים.

### גיבוי ושחזור אישיים

ייצוא מוצפן כולל רק תלמידות בבעלות היועצת, כולל כרטיסים בארכיון, הפגישות, המשימות והיומן. אין ייצוא כרטיסים משותפים, חשבונות, מפתחות AI, MFA, הרשאות שיתוף או יומן ביקורת. סיסמת גיבוי נפרדת באורך 16 תווים לפחות נגזרת באמצעות PBKDF2-SHA256 עם 600,000 איטרציות ומלח אקראי; התוכן מוצפן ומאומת באמצעות Fernet. הסיסמה אינה נשמרת בשרת. הגיבוי אינו תלוי במפתח הצפנת ההתקנה ולכן ניתן לייבא אותו גם בהתקנה אחרת עם סיסמת הגיבוי.

מועד יצירת הגיבוי האחרון מוצג בהגדרות, ותזכורת מופיעה גם במבט על לאחר שבעה ימים או אם טרם נוצר גיבוי. המועד מציין יצירת קובץ מוצפן, ולא אימות שהקובץ נשמר בדיסק. הייצוא מוגבל לתוכן לפני הצפנה עד 10MB. הממשק מייבא קבצים עד 15MB, והשרת מגביל בקשות שחזור ל־20MB.

שחזור מוסיף כרטיסים חדשים, בלי למחוק או לשנות כרטיסים קיימים ובלי להחזיר שיתופים. לכן עלולות להיווצר תלמידות ופגישות כפולות; יש לבדוק יומן לאחר הייבוא. שחזור אותו קובץ פעמיים באותו חשבון נחסם. הייבוא מאומת ונשמר בעסקה אחת. זהו גיבוי נתונים אישי, ואינו מחליף גיבוי PostgreSQL ותשתית המערכת.

### אימות דו־שלבי

ההגדרה באמצעות אפליקציית אימות מבוססת זמן, TOTP עם SHA-1 ושישה ספרות בכל 30 שניות. המפתח מוזן ידנית באפליקציה ונשמר מוצפן בשרת. ההגדרה דורשת סיסמה ואישור קוד תוך 10 דקות. נוצרים עשרה קודי שחזור חד־פעמיים; הם מוצגים רק בעת ההפעלה ונשמרים בשרת כגיבובים בלבד. שמרי אותם במקום מוגן לפני הכניסה מחדש.

הפעלה או כיבוי מבטלים את כל ההתחברויות. קוד שנוצל אינו מתקבל שוב, ולכן אחרי ההפעלה יש להמתין לקוד הבא באפליקציה. חמישה ניסיונות אימות שגויים נועלים את האימות ל־15 דקות. השעון בשרת ובמכשיר צריך להיות מסונכרן. שינוי סיסמה על ידי מנהלת אינו מבטל MFA. אם אבדו גם האפליקציה וגם קודי השחזור נדרשת התערבות מפעיל מוסמך במסד; אין מסלול עקיפה בממשק.

### אימות השינויים

בדיקות אוטומטיות משתמשות רק במסדים זמניים ובספקי AI מדומים: הרשאות מנהלת, שיתוף לצפייה וביטולו, ביטול JWT, העברת OTP בשירות האימות, וקטורי RFC 6238, מניעת שימוש חוזר, נעילה, הצפנת מפתחות, בידוד הגדרות AI, בדיקת חיבור, גיבוי ושחזור, סיסמת גיבוי שגויה ומיגרציה על מסד קיים. בדיקת דפדפן, Docker מקומי, ספק אמיתי ופריסת HTTPS דורשות אימות בסביבת ההתקנה.


## מייל מערכת ומרכז ניהול — בדומה ל־DOMix

למנהלת מופיע תפריט **ניהול מערכת** (`/admin`), עם מסך משתמשות (`/admin/users`) ומסך **מייל מערכת** (`/admin/email`). ניהול Gmail מוגבל למנהלות בלבד ודורש אישור סיסמה וקוד MFA אם הופעל. החיבור נעשה בדפדפן Google, בנפרד מההתחברות למרחב. שירות AUTH הקיים נשאר באותה ארכיטקטורה.

### הגדרת Google

הגדירי בקובץ .env המקומי בלבד, ללא העלאה לגיט:

```dotenv
GMAIL_CLIENT_ID=your-google-web-client-id
GMAIL_CLIENT_SECRET=your-google-web-client-secret
```

אפשר להשתמש בלקוח Web OAuth קיים שבבעלותך, אבל חובה להוסיף לו את כתובת ההפניה של מרחב ולהפעיל Gmail API. בפיתוח המקומי כתובת ההפניה היא:

```text
http://localhost:8088/api/email/gmail/callback
```

בפריסה היא CLIENT_ORIGIN בתוספת `/api/email/gmail/callback`. אפשר להגדיר GMAIL_REDIRECT_URI אם ה־API נחשף בכתובת אחרת. במסך המיילים מוצגת הכתובת המדויקת. Google צריכה לאפשר `openid email https://www.googleapis.com/auth/gmail.send` לחשבון השולח. הגדרות מסך ההסכמה, משתמשות הבדיקה ואימות האפליקציה נקבעות בפרויקט Google. אין לשנות את ההפניות שכבר משמשות את DOMix או את ההתחברות שם.

לאחר עדכון ההגדרות הריצי את סקריפט start-local, היכנסי כמנהלת, פתחי מייל מערכת ולחצי חיבור Gmail. בחרי את החשבון המיועד לשליחת כל מיילי המערכת. הזיני שם שולח, כתובת למענה וחתימה, ושגרי מייל בדיקה לכתובת שבשליטתך. אין להזין סיסמת Gmail במרחב. מייל בדיקה מצורף לתור; מצב „נשלחה” מציין ש־Gmail API קיבל את ההודעה, ולא מבטיח שהגיעה לתיבת הנמען.

טוקן החיבור מוצפן באמצעות DATA_ENCRYPTION_KEY ואינו מוחזר לממשק. מצב OAuth חד־פעמי נשמר כגיבוב במסד ל־10 דקות, עם PKCE וקישור ל־cookie של הדפדפן. בקבלת החיבור נבדקים שוב הרשאת המנהלת, החשבון הפעיל וגרסת ההתחברות; חיבור שהתיישן אחרי החלפה או ניתוק נדחה. לוג הגישה ב־Nginx כבוי לכתובת החזרה מ־Google, כדי לא לתעד קודי אישור. ניתוק מבטל גם גיבוי מסביבת השרת ומבטל הודעות ממתינות. הוא אינו מבטל הרשאות אצל Google; ניתן להסירן גם בחשבון Google.

למי שכבר מחזיקה טוקן שליחה תקין, יש אפשרות fallback ב־GMAIL_EMAIL ו־GMAIL_REFRESH_TOKEN. לאחר חיבור או ניתוק דרך הממשק ההגדרה במסד קובעת. אין צורך בערכים הללו לחיבור דרך המסך.

### הודעות מעוצבות ותור משלוחים

כל המיילים משתמשים בעיצוב מרחב, כיווניות RTL, עברית, כפתור לפתיחה במערכת, שם שולח וחתימה. תוכן וחתימה עוברים escaping; אין HTML חופשי מהמשתמשת. נשלחות הודעות על פתיחת חשבון, בחירת סיסמה, אימות כתובת, הפעלה וכיבוי של MFA, שינוי חשבון בידי מנהלת, שיתוף לצפייה ותזכורת שבועית לגיבוי. ההודעות אינן מצרפות שמות תלמידות, תמלולים, סיכומים, משימות או קבצי גיבוי. רק פרטי החשבון של הנמענת והודעה כללית נשלחים לספק המייל.

שירות email-worker נבנה מאותה תמונת Python של שרת הנתונים. הוא שולח ברקע תור שנשמר במסד עם תוכן מוצפן. תקלה במייל אינה מבטלת יצירת משתמשת או פעולות אחרות. יש ניסיון חוזר מוגבל לכשלים שהתרחשו לפני השליחה או למגבלת שימוש ברורה; timeout או תשובת שרת לא ודאית בזמן שליחה מסומנים „תוצאה לא ודאית” ללא משלוח אוטומטי נוסף. קריסה אחרי תפיסת הודעה לטיפול אינה גורמת לשליחה כפולה אוטומטית. תזכורות גיבוי נבדקות מדי שעה ונשלחות לכל היותר אחת בשבוע לכל חשבון פעיל ומאומת, כאשר אין גיבוי מהשבוע האחרון.

היסטוריית 50 המשלוחים האחרונים מוצגת למנהלת בלבד, ללא תוכן או טוקנים. לאחר שליחה או כשל סופי גוף ההודעה נמחק מהתור. הודעות ממתינות פגות אחרי 24 שעות; קישורי בחירת סיסמה פגים אחרי 30 דקות. אם שירות המייל לא היה זמין עד פקיעת הקישור, יש לבקש קישור חדש. תעודת NetFree מועברת גם ל־email-worker דרך compose.local-ca.yml; אימות TLS נשאר פעיל.

```powershell
docker compose logs --tail 50 email-worker
```

### איפוס סיסמה ואימות כתובת

במסך הכניסה מופיע „שכחתי סיסמה”. התגובה זהה לכתובת קיימת ולא קיימת, וקישור נשלח רק לחשבון מורשה פעיל כאשר המייל מחובר. הקישור תקף ל־30 דקות ולשימוש אחד; בקשות חוזרות מוגבלות גם לפי חשבון. אחרי איפוס כל ההתחברויות והקישורים הישנים מבוטלים. MFA נשאר מופעל ונדרש בכניסה הבאה. גם שינוי חשבון בידי מנהלת או שינוי MFA מבטלים קישורים ישנים.

טוקנים של קישורים נשמרים כגיבובים בלבד. קישור המייל משתמש ב־fragment שנקרא בדפדפן ומוסר משורת הכתובת, ולא נשלח ב־URL של בקשת HTTP. האישור עצמו הוא פעולת POST. במסך האבטחה ניתן לבקש אימות כתובת; האישור תקף ל־24 שעות ואינו מעניק הרשאות נוספות. אין הרשמה ציבורית, ואין חסימה חדשה של חשבונות קיימים בגלל אימות כתובת.

הבדיקות משתמשות ב־Gmail מדומה בלבד: הרשאות מנהלת, PKCE, cookie ומצב חד־פעמי, הצפנת טוקן, דחיית חיבור שהתיישן, MIME ועיצוב RTL, escaping, מניעת הזרקת כותרות, אי־שליחה חוזרת במצב לא ודאי, ניתוק fallback, קישורים חד־פעמיים ופגי תוקף, שמירת MFA, ביטול קישורים ישנים ותזכורות ללא פרטי תלמידות. חיבור ושליחה אמיתיים מחייבים הגדרת Google והרשאת החשבון שלך.
